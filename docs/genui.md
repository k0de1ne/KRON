# Интерфейс под задачу (generative UI)

Вместо переписки kron собирает рабочий интерфейс под конкретную задачу и конкретного человека: панель сравнения с фильтрами и графиком, структуру проекта, пульт машины с терминалом, редактор с диффом. Начальный экран почти пустой — поле ввода с микрофоном и ваши прошлые интерфейсы.

Режим включается чипом «Интерфейс» под полем ввода (он же по умолчанию). «Агент» и «Чат» остались как были.

## Как это работает

```
 запрос (текст или голос)
   │
   ▼
 hub: genui::turn ─ intent (классификатор) ─ профиль ─ подходящий шаблон ──► черновик сразу (draft)
   │
   ▼
 агент kron (те же инструменты, права, стоп, подтверждения)
   │  смотрит реальные данные: файлы, команды, веб
   │  render_ui(surface) / patch_ui(части) / update_data(patches) / remember(note)
   ▼
 surface: компоненты + данные + версии  ──SSE `surface`──►  gen.js рисует из каталога
                                                              │
     ▲            [ui-action] {name, context}   ◄── кнопка с event
     │            /api/surfaces/:id/data        ◄── правка, фильтр, галочка, перетаскивание
     │            /api/surfaces/:id/exec        ◄── кнопка с tool, терминал (с подтверждением)
     │            /api/surfaces/:id/live        ◄── живые источники по таймеру (без модели)
     │            /api/surfaces/:id/layout      ◄── человек двигает и скрывает блоки
     │            [ui-edit] {component, request} ◄── «Изменить» у блока
     │            /api/surfaces/:id/signal      ◄── чем пользуются, «Удобно» / «Не то»
     └──────────── профиль и шаблоны ◄──────────────┘
```

1. **Намерение.** Быстрый классификатор (`genui/profile.rs`, ключевые основы слов на русском и английском) относит запрос к виду задачи: `compare`, `project`, `server`, `code`, `data`, `plan`, `write`, `chat`. Модель видит догадку и может назвать вид сама (`render_ui.intent`). «Просто поговорим» — `chat`: агент отвечает текстом, интерфейса нет, экран остаётся минимальным диалогом.
2. **Контекст.** В системный промпт попадают: каталог компонентов, пожелания человека, какие компоненты он реально использует в задачах этого вида, последние задачи, а для продолжения — текущий интерфейс вместе с правками человека.
3. **Генерация.** Агент собирает данные своими обычными инструментами и вызывает `render_ui` один раз с целым интерфейсом. Хаб проверяет его (`genui/surface.rs::validate`): известные компоненты, уникальные id, существующие дети, один корень, нет циклов, разумный размер. Ошибки уходят модели текстом, она исправляет; после трёх неудач в одном ответе — отвечает текстом.
4. **Отображение.** Клиент (`src/ui/gen.js`) рисует компоненты из каталога в единой дизайн-системе. Данные отделены от структуры: компоненты читают их через `{"path": "/rows"}`, и изменение данных перерисовывает только зависящие компоненты.
5. **Взаимодействие.** Фильтры, сортировка, поиск, правка ячеек, галочки, перетаскивание, вкладки, ползунки работают сразу, без модели, и сохраняются на хаб. Кнопки делают одно из трёх: локальное действие (`functionCall`), запуск инструмента на машине (`tool`, с подтверждением) или вопрос агенту (`event` → новый ход с `[ui-action] {...}`), и агент обновляет интерфейс через `update_data` — не перестраивая его.
6. **Сохранение.** Интерфейс живёт на хабе (`~/.kron/genui/surfaces/`), привязан к чату, но не к модели и не к устройству: откройте его завтра с телефона — данные и ваши правки на месте. Каждое изменение (агента или ваше) — версия; «Отменить» и «История версий» возвращают любую.
7. **Жизнь без модели.** Интерфейс не снимок: он сам обновляется, считает и предупреждает (см. «Живой интерфейс» ниже), а человек может его переставить или ткнуть в блок и сказать, что изменить.
8. **Переиспользование.** Удобный интерфейс (вы им пользуетесь, закрепили или нажали «Удобно») становится шаблоном для своего вида задач. На похожий запрос kron сразу показывает этот вид как черновик (десятки миллисекунд), а агент сохраняет структуру и меняет содержимое. Пока вы печатаете, начальный экран предлагает открыть уже существующий похожий интерфейс вместо нового.

## Живой интерфейс

Агент нужен, чтобы построить и перестроить интерфейс, но не чтобы им пользоваться. Всё, что можно делать без модели, делается без неё.

**Формулы.** Везде, где компонент принимает привязку `{"path"}`, можно написать `{"expr": "..."}` — значение считается на устройстве мгновенно, при каждом изменении данных, которые формула читает:

```json
{"id": "done", "component": "Metric", "label": "Готово", "value": {"expr": "count(/tasks/*/done, true) + ' из ' + len(/tasks)"}}
{"id": "cpu", "component": "Badge", "text": {"path": "/cpu"}, "tone": {"expr": "/cpu > 80 ? 'danger' : 'ok'"}}
{"id": "down", "component": "Table", "rows": {"expr": "where(/services, 'status', 'down')"}, "visible": {"expr": "len(where(/services, 'status', 'down')) > 0"}}
```

- данные: `/путь`, внутри шаблона детей `@поле` (и `@` — сам элемент), `*` собирает значения из всех элементов: `/rows/*/price`;
- `12`, `'текст'`, `true`, `false`, `null`; `+ - * / %` (вокруг `/` пробелы — иначе это путь), `== != < <= > >=`, `&& || !`, `a ? b : c`, `a ?? b`; `+` склеивает текст;
- функции: `sum avg min max len count round abs floor ceil fmt pct join where pluck sort first last uniq contains lower upper if now time ago`.

Свой разборщик без `eval`: формула не может ни выполнить код, ни выйти за пределы данных интерфейса. Ошибка в формуле показывается пометкой на компоненте, остальное работает.

**`visible`.** Любой компонент показывается, только пока значение `visible` истинно (пустой список, `0`, `""`, `false`, `null` — ложь).

**Живые данные (`sources`).** Команды, которые хаб выполняет по таймеру, пока интерфейс открыт, и кладёт результат в данные:

```json
"sources": [
  {"id": "load", "command": "cat /proc/loadavg", "target": "/load", "parse": "number", "every": 5, "keep": 60},
  {"id": "disk", "command": "df -k /", "target": "/disk", "parse": "table", "every": 60},
  {"id": "log", "tool": {"name": "read_file", "args": {"file_path": "build.log"}}, "target": "/log", "parse": "lines"}
]
```

- `parse`: `text`, `lines`, `number` (первое число), `json`, `table` (колонки по пробелам под строкой заголовка → `[{...}]`), `kv` (строки `ключ: значение` → объект);
- `every` — секунды (от 2), `0` — только при открытии и по кнопке; `keep: N` — дописывать `{t: "ЧЧ:ММ:СС", ts, value}` и хранить последние N: линейный график по `t` становится живым;
- инструменты: `shell`, `read_file`, `list_dir`, `grep_files`. Команда выполняется на машине чата и по его правилам: в «Только чтение» — только чтение файлов; в «Спрашивать» команду `shell` нужно один раз разрешить (интерфейс показывает её точный текст и частоту). Разрешение привязано к точной команде: агент изменил её — kron спросит снова;
- живые значения не создают версий (иначе «Отменить» утонуло бы в них) и не обновляются, пока вкладка скрыта; вернулись — данные догоняются сразу. Пауза, «Обновить всё» и ошибки каждого источника — по кнопке-пульсу в шапке;
- кнопка может обновить источник сразу: `{"functionCall": {"call": "refresh", "args": {"source": "load"}}}`.

**Оповещения (`alerts`).** `{"id": "hot", "when": "/load > 4", "text": {"expr": "'Нагрузка ' + /load"}, "tone": "danger"}` — пока условие истинно, сверху интерфейса висит плашка; когда оно становится истинным, приходит уведомление (системное, если интерфейс не на экране и уведомления разрешены — пункт в меню живых данных) и телефон вибрирует.

**Точечные правки агентом (`patch_ui`).** Вместо пересылки всего интерфейса агент присылает только изменения: `set` (компоненты, заменяемые или добавляемые по id), `remove`, `sources` / `remove_sources`, `alerts`, `data`. Результат проверяется целиком, компоненты, до которых больше не дотянуться от корня, убираются. Быстрее, дешевле и не трогает то, к чему человек привык.

**Правка человеком.** Карандаш в шапке (на телефоне — меню «⋯ → Настроить интерфейс») включает режим настройки: у каждого блока появляются «выше», «ниже», «скрыть» — это делается сразу, без модели, и становится версией (отменяется как обычно) — и «Изменить»: человек пишет, что сделать именно с этим блоком («покажи как график по дням»), агент получает `[ui-edit] {"component", "type", "request"}` и меняет только его через `patch_ui`.

## Почему так: A2UI, AG-UI и другие подходы

| Подход | Что это | Что взято |
|---|---|---|
| [A2UI](https://a2ui.org/specification/v0.9-a2ui/) (Google, v0.9; v1.0 — кандидат) | Декларативный JSON: плоский список компонентов со ссылками на детей по id, отдельная модель данных с JSON Pointer, привязки `{"path"}`, шаблоны детей `{path, componentId}`, действия `event` / `functionCall`, каталог доверенных компонентов на клиенте | **Формат surface целиком**: компоненты v0.9 (`"component": "Text"`, v0.8-форма `{"Text": {...}}` тоже принимается), привязки, шаблоны, действия, `[ui-action]` с `name` / `context` / `component`. Свой каталог (таблицы, графики, дерево, терминал) вместо базового |
| [AG-UI](https://docs.ag-ui.com) (CopilotKit) | Протокол событий агент ↔ фронтенд поверх SSE: текст, вызовы инструментов, снимки и дельты состояния (JSON Patch), ошибки | У kron уже был такой поток событий (`text`, `reasoning`, `tool_start/end`, `ask`, `error`, `done`). Добавлено одно событие `surface` — снимок состояния, как `STATE_SNAPSHOT`. Изменения данных от человека — пары `{path, value}` |
| MCP Apps / Apps SDK, MCP-UI | Агент присылает HTML, клиент показывает его в песочнице и общается через `postMessage` | Компонент `Html`: свой код агента в `iframe sandbox="allow-scripts"` без доступа к хабу, без сети (CSP), с API `kron.action`, `kron.set`, `kron.data` и CSS-переменными дизайн-системы |
| Vercel AI SDK `streamUI` | Инструменты модели возвращают React-компоненты | Идея «UI = результат вызова инструмента»: `render_ui` — обычный инструмент агента, видимый в шагах |

**Зависимостей не добавлено.** SDK AG-UI и рендереры A2UI рассчитаны на React/Angular/Lit и TypeScript-сборку; интерфейс kron — встроенный в бинарник ванильный JS без сборки, работающий офлайн на телефоне. Протоколы реализованы по спецификациям, компактно: рендерер — один файл, проверка — один модуль на Rust.

## Каталог

Полное описание, которое видит модель, — `genui::CATALOG` в `src/genui/mod.rs`.

- Компоновка: `Column`, `Row`, `Grid` (адаптивная сетка, одна колонка на телефоне), `Card`, `Tabs`, `Collapsible`, `Divider`.
- Содержимое: `Heading`, `Text` (markdown), `Badge`, `Metric`, `Progress`, `KeyValue`, `Code`, `Diff`, `Log`, `Image`.
- Данные: `Table` (сортировка, поиск, фильтр по значению из другого компонента, выбор строк, правка ячеек), `Chart` (bar, hbar, line, area, donut; легенда переключает серии, подсказки по наведению и касанию), `List` (галочки, перетаскивание, удаление), `Tree`.
- Ввод: `TextField`, `Select`, `ChoicePicker`, `CheckBox`, `Slider`, `Editor`, `Button`, `Terminal`.
- Своё: `Html` в песочнице — когда каталога не хватает.

Цвета графиков — проверенная категориальная палитра (фиксированный порядок, отдельные шаги для тёмной темы), текст всегда цветами текста. Сломанный компонент показывает пометку и не роняет остальной интерфейс; если не рисуется весь интерфейс — kron показывает переписку текстом и предлагает предыдущую версию.

## Контроль у человека

- Агент работает с теми же правами, что выбраны чипом: «Спрашивать» — каждая команда и правка файла ждёт подтверждения (карточка открывается в панели шагов сама), «Только чтение» — только смотреть.
- Кнопки с `tool` и терминал выполняются хабом без модели, но по правилам чата: в «Только чтение» команды запрещены, в «Спрашивать» хаб требует подтверждения, и интерфейс показывает точную команду. Кнопки `danger` подтверждаются всегда. Каждый запуск пишется в «Журнал команд» интерфейса.
- «Стоп» всегда под рукой (строка статуса над полем ввода и Esc). Шаги агента и переписка — кнопка со списком в шапке.
- Отмена: Ctrl+Z или кнопка в шапке, «История версий» — любая версия.
- «Настройки → Память и интерфейсы»: что kron о вас знает — пожелания (добавить, удалить), запомненные виды (удалить), чем вы пользуетесь; сброс обучения.

## Голос

В браузере — Web Speech API (`SpeechRecognition`), в приложении для Android — системное распознавание речи через мост `KronAndroid.listen`. Где ни того ни другого нет, кнопка микрофона скрыта (голосовой ввод клавиатуры по-прежнему работает).

## API хаба

- `GET /api/surfaces` — интерфейсы, новые первыми; `GET` / `DELETE /api/surfaces/:id`.
- `POST /api/surfaces/:id/data {patches: [{path, value}]}` — правки человека (правки одного поля в течение 30 с — одна версия).
- `POST /api/surfaces/:id/undo {version?}`, `GET /api/surfaces/:id/versions`.
- `POST /api/surfaces/:id/signal {kind: open|interact|like|dislike|pin|unpin, used: [компоненты], count}`.
- `POST /api/surfaces/:id/exec {tool, args, confirmed}` — `shell`, `read_file`, `list_dir`, `grep_files`; 409 «needs confirmation», 403 в режиме чтения.
- `POST /api/surfaces/:id/live {source, tz}` — выполнить живой источник и записать результат (`{ok, path, value}` или `{ok: false, error}`); 409 «needs approval», 403 в режиме чтения. `tz` — смещение браузера от UTC в минутах, для подписей времени.
- `POST /api/surfaces/:id/approve {sources: [id]}` — разрешить команды этих источников.
- `POST /api/surfaces/:id/layout {op: move|hide, id, dir}` — человек переставил или скрыл блок (новая версия).
- `GET /api/genui/profile`, `GET /api/genui/match?q=`, `POST /api/genui/notes {text}`, `DELETE /api/genui/notes/:id`, `DELETE /api/genui/templates/:id`, `POST /api/genui/reset {notes}`.
- `POST /api/runs` с `mode: "ui"`; событие рана `surface {surface, draft}`.

## Тесты

- `cargo test` — проверка и нормализация surface, JSON Pointer, версии и отмена, классификатор, обучение и шаблоны, инструменты агента, разбор сломанных аргументов, `patch_ui`, перестановка и скрытие блоков, живые источники (проверка, разбор вывода, `keep`, разрешения).
- `node tests/ui/surface.test.cjs` (после `cargo build`, нужен Playwright с Chromium) — рендерер в настоящем браузере на телефонном экране: привязки и шаблоны детей, сортировка, фильтр, поиск, правка ячеек, вкладки, график и легенда, список, поля, локальные действия, песочница `Html`, кнопка-команда с подтверждением, сохранение на хабе, отмена, обучение, формулы и `visible`, живой источник с разрешением и повтором по таймеру, оповещение, режим настройки и `[ui-edit]`. Запускается в CI.
