# Интерфейс, который пишет агент

У kron нет готового интерфейса для работы. Весь экран, которым вы пользуетесь, — веб-приложение, которое пишет и переписывает сам агент. Каталога компонентов, шаблонов и заготовленных режимов нет: агент решает, чем быть интерфейсу, на каком фреймворке его делать и как интерфейс с ним разговаривает.

- В первый раз пусто: одна строка ввода. Первое же сообщение агент превращает в интерфейс — чат, канбан, граф с карточками, пульт сервера, что подходит.
- Хотите настройку, кнопку, страницу — скажите, и он её допишет. Не нравится — скажите, и он переделает.
- Интерфейс один на всё, живёт на хабе и одинаков с телефона и с ПК.

## Что написано заранее (ядро)

Ядро — то, что агент изменить не может. Оно намеренно маленькое.

| Что | Где | Зачем |
|---|---|---|
| Отдача интерфейса | `/` и любые пути → файлы `~/.kron/ui/` | Агент пишет туда инструментами `ui_write_file`, `ui_apply_patch`, `ui_read_file`, `ui_list_dir`, `ui_download` (только внутри этой папки). Путь без расширения, которого нет на диске, отдаёт `index.html` — для приложений со своей маршрутизацией. |
| Версии | git в `~/.kron/ui/` | После каждого ответа агента изменения коммитятся. Вернуть любую версию — на странице `/kron/`. Без git версий нет, остальное работает. |
| Аварийная страница | `/kron/` | Работает, даже если интерфейс сломан или пуст: поле ввода агенту, версии, вход в служебный режим. Пока интерфейса нет, `/` показывает её. |
| Служебный режим | `/kron/app` | Прежний интерфейс kron: вход в подписки, модели, настройки, обычный чат. |
| Данные интерфейса | `/api/ui/data/:key` → `~/.kron/ui-data/` | Где интерфейс хранит задачи, заметки и всё своё. Лежат вне папки интерфейса: откат версии их не трогает. Агент читает их инструментом `ui_data`. |
| Замки | `/api/locks`, `/kron/confirm` | См. ниже. |
| SDK (по желанию) | `/kron/sdk.js` | `kron.api` (с замками), `kron.send` (разговор с агентом), `kron.data`. Агент может им не пользоваться и работать с HTTP API напрямую. |

Всё остальное — обычный HTTP API хаба (разговоры, запуски агента и их события, файлы на машинах, конфиг, вход в подписки). Его описание агент получает в системном промпте: `src/prompts/face.md`.

## Замки: защита от самого агента

Что-то должно быть недоступно агенту, даже если он напишет для этого код: сейф с паролями, ключи, платежи, удаление, настройки. Для этого есть замки.

- Замок закрывает вызовы хаба (метод и путь, со всем, что под ним), например `GET /api/ui/data/vault`. Поставить замок может кто угодно, в том числе агент: это только ужесточает правила.
- Закрытый вызов отвечает `423` с номером подтверждения. Подтверждает человек на странице kron `/kron/confirm`: видит, что именно выполняется, и вводит пароль. В первый раз там же задаётся пароль.
- Подтверждение пропускает ровно тот запрос, который человек видел (метод, путь, тело), один раз и в течение двух минут.
- Снять замок и сменить пароль — тоже закрытые вызовы. Агент может ставить замки, но не снимать их и не узнать пароль.
- Страница подтверждения не встраивается в интерфейс (`X-Frame-Options: DENY`, `frame-ancestors 'none'`) и открывается в своём контексте браузера (`Cross-Origin-Opener-Policy: same-origin`). Поэтому код интерфейса не может ни прочитать поле пароля, ни нажать кнопку за человека.
- Закрытые данные не видит и инструмент агента `ui_data`.
- После пяти неверных паролей подряд — минута паузы.
- Забыли пароль — удалите `~/.kron/locks.json` на машине с хабом. Снимутся и все замки: для этого нужен доступ к машине, а не к интерфейсу.

Чего замки не делают. Агент в режиме «Полный доступ» выполняет любые команды на машинах, в том числе на машине с хабом. Замок защищает вызовы через хаб и данные от инструментов интерфейса, но не от команды `rm ~/.kron/locks.json` на той же машине. Если это важно, держите агента в режиме «Спрашивать» или «Только чтение» для машины с хабом: тогда такую команду придётся подтвердить вам. Ещё одно: интерфейс может нарисовать поддельное поле пароля. Вводите пароль только на странице с подписью «Страница kron, не вашего интерфейса» по адресу `/kron/confirm`.

## Как агент работает с интерфейсом

- Запросы из интерфейса идут как `POST /api/runs` с `mode: "ui"`. В этом режиме агент получает инструменты `ui_*` и промпт `src/prompts/face.md`, где описаны устройство, API и замки, а также текущее содержимое папки.
- Интерфейс сам решает, как показывать ответы и шаги агента: события запуска приходят потоком (`GET /api/runs/:run/events`). Когда приходит `tool_end` инструмента `ui_*`, интерфейс перезагружает себя или изменившуюся часть.
- Библиотеки агент может скачать в папку интерфейса (`ui_download`), чтобы всё работало без интернета. Сборки на хабе нет: файлы отдаются как есть.
- Маленькие локальные модели интерфейс не пишут: им достаётся обычный разговор.

## Тесты

- `cargo test` — пути внутри папки интерфейса, инструменты `ui_*`, версии и откат через git, замки (пароль, одноразовое подтверждение ровно того запроса, неснимаемость).
- `node tests/ui/kernel.test.cjs` (после `cargo build`, нужен Playwright с Chromium) проверяет в браузере на экране телефона:
  - пустой старт и ошибку без модели;
  - интерфейс, записанный на диск, и маршрутизацию;
  - закрытую `.git`;
  - SDK;
  - замок с паролем на странице kron: первый пароль, повторный замок, неверный пароль, неснимаемость;
  - заголовки изоляции;
  - служебный режим.

  Запускается в CI.
